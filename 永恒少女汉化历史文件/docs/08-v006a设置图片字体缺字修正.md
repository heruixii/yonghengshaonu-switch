# 《永恒少女》NS 汉化阶段 08：v006a 设置图片字体缺字修正

## 1. 实机反馈

v006 实机确认：

```text
设置等界面出现大量缺字情况
```

因此立即停止继续扩大图片 UI 范围，先回查 v006 的图片字体链。

---

## 2. 根因

v006 的 `04_scripts/localize_settings_images.py` 在制作中文 PNG 时，优先直接读取了干净 RomFS 中的原始 TTC：

```text
02_romfs/merged-v1.0.3/System/dfgotp5.ttc
02_romfs/merged-v1.0.3/System/dfmrg5_u.ttc
02_romfs/merged-v1.0.3/System/dfhsr4.ttc
```

这些原始 TTC 的 Windows format-4 cmap 本来就存在非标准边界布局。此前运行时字体构建流程已经专门对其进行过 cmap 规范化并补充简中字形，但 v006 图片脚本错误地绕过了构建后的字体，直接把原始 TTC 交给 Pillow/FreeType。

实测 FontTools 读取原始 TTC 时会直接报告 cmap glyph-index 越界；Pillow 虽然能够打开字体文件，却不能据此保证中文字符映射正确，因此最终 PNG 中出现大量缺字/错误字形。

这属于 **图片生成字体选择错误**，不是剧情或动态 UI 的运行时字体补丁失效。

---

## 3. 运行时 TTC 复核

v005/v006 LayeredFS 中携带的三个 TTC 与原始 RomFS TTC 哈希不同，属于已经规范化和补字后的构建字体。

重新用 FontTools 检查设置图片所需的全部 184 个非 ASCII 中文字符：

```text
dfgotp5.ttc
  face 0 missing = 0
  face 1 missing = 0
  face 2 missing = 0

dfhsr4.ttc
  face 0 missing = 0
  face 1 missing = 0
  face 2 missing = 0

dfmrg5_u.ttc
  face 0 missing = 0
  face 1 missing = 0
  face 2 missing = 0
```

因此动态文本/剧情使用的运行时字体继续沿用 v005，不重新修改。

---

## 4. 图片字体修正

图片是预烘焙 PNG，不需要把生成字体本身打入补丁。

修正后的脚本改为只使用本机完整中文字体源，优先：

```text
C:\Windows\Fonts\msyh.ttc
```

并在开始重绘之前通过 FontTools 对实际目标字符集执行硬校验：

```text
目标非 ASCII 字符 = 184
image_font_missing = 0
```

如果所选字体存在任何目标字符缺失，脚本现在会直接报错并停止生成，而不是继续输出可能含缺字的 PNG。

新的图片输出目录：

```text
03_text/ui/rendered-v006-fontfix/
```

重新生成：

```text
configmenu 页面                 7
configmenubutton 状态精灵      10
--------------------------------
PNG                            17
```
